# Tube B 协作与实验规则

这套结构用于防止多个 AI 围着同一个解反复改、口径漂移，或者用投票代替数值验证。机器执行合同见 `contracts/tube_collaboration_v1.json`。

## 谁负责什么

| 角色 | 直接负责 | 明确不能做 |
|---|---|---|
| `or-tube-lead` | 冻结假设、输入哈希、实验卡和预算账本 | 编造或投票决定数值 |
| `or-tube-geometry` | 管轴、端部轮廓、共切矩阵稳定性 | 把点云模型说成 STEP 碰撞证明 |
| `or-tube-q1q2` | Q1 母材与切换、Q2 固定分配共切 | 改几何或宣称未证明的最优 |
| `or-tube-q3` | 联合排样、下界与停止判断 | 改需求或把启发式说成全局最优 |
| `or-tube-q4` | 三批次、余料、束搜索与 Q4 下界 | 重复使用余料或隐藏库存 |
| `or-tube-redteam` | 独立重算、篡改攻击、结论审计 | 帮求解器修答案或豁免失败门禁 |

只有本地求解器产生候选，独立验证器通过后数字才有效。Agent 的文字意见、排名或投票都不是数值证据。

## 精力分配

基线求解与必要门禁不计入可自由分配的实验预算。剩余精力固定分配为：

- 几何与共切可靠性：20%；
- Q1/Q2：10%；
- Q3：25%；
- Q4：45%。

若几何门禁为红，临时调整为 35/10/25/30；只有独立分辨率门禁通过后才恢复 20/10/25/45。当前几何门禁已通过，因此使用正常分配。

Q4 内部推荐继续按 40/25/20/10/5 分配：未来价值与分层 beam、剩余需求共切 initializer、宽度和新种子、定向删除—修复、严格验证。

## 每次实验的硬规则

1. 一张实验卡只允许改一个因素；先写假设、基线、种子、预算和验收条件，再运行。
2. 输入哈希、需求、单位、母材规格、200 mm 余料阈值和目标顺序保持冻结。
3. 目标顺序固定为：硬约束 → 新购母材最少 → 共切最大 → 切换最少。废料只作诊断。
4. 随机搜索必须记录种子；失败和超时实验也保留，不能只展示成功结果。
5. 候选必须通过需求守恒、容量、余料 ID 单次使用、库存链、物料平衡和输入哈希检查。
6. Q4 找到 250000 mm 且通过 strict + red-team 时，才可宣布采购主目标最优；否则必须报告下界和差距。
7. 点云几何通过稳定性门禁不等于 STEP 实体无碰撞证明；工程应用前仍需 CAD 碰撞核。

## 门禁命令

```bat
orpath.bat doctor
orpath.bat tube-collab-gate
orpath.bat tube-geometry-gate
orpath.bat tube-redteam-gate
```

协作门禁检查合同、六个角色与实验模板；几何门禁用独立实现重建；红队门禁主动伪造共切、需求、库存、下界和输入哈希，要求验证器全部拒绝。
